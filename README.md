# Parly Relayer

Production relayer runtime for Parly operators.

## What this project is

This repository contains the Parly relayer runtime, registry client, encrypted message handling, pending reconciliation, and execution helpers needed to operate a relayer without the full protocol workspace.

## Who this project is for

This project is for operators who want to support Parly private payment activity.

A relayer can support:

- ingress duties for supported deposit work
- payout duties for supported private payout routes
- pending-state reconciliation
- registry heartbeat updates for public app discovery

The same operator identity can support both Tempo asset lanes:

- USDC.e
- USDT0

The assets remain separate. A relayer may serve both lanes, but settlement, accounting, fees, and validation stay asset-specific.

## Quickstart

```bash
cp .env.example .env
pnpm install
pnpm keygen:box
pnpm smoke:standalone
pnpm start
pnpm reconcile:pending:loop
```

## Register for public app discovery

After setup, open:

```text
https://parly.fi/relayer
```

You will need:

- the relayer execution address
- the Base64 relayer public key generated by `pnpm keygen:box`
- a browser wallet connected to the relayer execution address
- a wallet signature proving control of that address
- acknowledgement of ingress duties, payout duties, or both

Registration is automatic when validation passes and a public registry slot is available.

## Required environment

- `RELAYER_PRIVATE_KEY`
- `RELAYER_BOX_PRIVATE_KEY_B64`
- `RELAYER_ADDRESS`
- `DATABASE_URL`
- `TEMPO_RPC_URL`
- `TEMPO_CHAIN_ID=4217`
- `SETTLEMENT_DOMAIN_ID=4217`
- `WAKU_CONTENT_TOPIC`

## Optional registry environment

Set this if you want the runtime to keep its public registry entry and heartbeat current:

- `RELAYER_REGISTRY_API_BASE_URL`

## Optional relayer-owned execution worker

These variables are required only when you operate relayer-owned one-time execution:

- `PHASE3_RELAYER_OWNED_EXECUTION_WORKER_ENABLED`
- `PHASE3_EXECUTION_DATABASE_URL`
- `PHASE3_EXECUTION_PAYLOAD_ENCRYPTION_KEY_B64`
- `PHASE3_RELAYER_OWNED_EXECUTION_WORKER_ID`
- `PHASE3_RELAYER_OWNED_EXECUTION_LEASE_MS`
- `PHASE3_RELAYER_OWNED_EXECUTION_POLL_MS`

Live broadcast is gated by:

- `PHASE3_FINALIZER_ENABLED`
- `PHASE3_LIVE_TRANSACTIONS_ENABLED`
- `PHASE3_RELAY_OUTBOUND_BROADCAST_ENABLED`
- `PHASE3_PAYOUT_EXECUTION_ENABLED`

## Operator expectations

- Keep the relayer online.
- Keep the pending reconciler online.
- Keep registry heartbeat updates healthy if listed.
- Keep USDC.e and USDT0 balances, jobs, and accounting separate.
- Secure the execution private key and sealed-box private key.
- Monitor gas, route costs, and execution profitability.
- Do not broadcast work that fails local validation.

## Safety notes

- Use `SETTLEMENT_DOMAIN_ID=4217` for Tempo.
- Do not configure browser-public credentials as relayer secrets.
- Do not reuse treasury, admin, or user wallets as relayer execution wallets.
- Keep live broadcast flags disabled unless you understand the route and operator responsibility they activate.
